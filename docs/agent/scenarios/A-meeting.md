# 시나리오 A — 회의 시연 (영상 메인 장면)

예시 스페이스(`npm run seed`로 만드는 "심화프로젝트랩 5조 · 미티")의 네 번째 회의.
이미 확정된 결정을 근거로 미티가 끼어든다. 이 대본으로 가짜 음성을 만들고(`voice/fake_meeting.py`),
텍스트 재생으로 판단을 시험하고(`scripts/live-replay.ts`), 화면 목업 데이터로도 쓴다.

## 회의 설정 (StartMeetingReq)

- title: 회의 4 — 대회 준비
- participants: 기헌, 준영, 태은, 지호
- intensity: high
- agenda:
  1. 시연 영상 구성 — expected: ["장면 순서 확정"]
  2. 디스코드 연동 범위 — expected: ["이번에 만들 범위 결정"]
  3. 리허설 — expected: ["날짜", "담당자"]

## 근거가 되는 HEAD 결정 (seed 결과, 상태 agreed)

- "입구는 웹 중심, 디스코드 봇은 2단계" (회의 3, 2026-10-10). 지호가 "봇 없으면 회의록 안 읽는 문제는 안 풀린다"는 의견을 남김
- "브라우저 녹음과 녹취 붙여넣기 함께 지원" (회의 3 이전에 확정, "클로바노트 녹취 붙여넣기만"을 대체)

## 대본

`[미티 기대]` 줄은 사람이 말하는 줄이 아니라 정답 표시다. 재생 평가는 이 표시와 실제 미티 행동을 비교한다.

```
기헌: 오늘 안건 세 개. 시연 영상 구성, 디스코드 연동 범위, 리허설.
태은: 영상은 회의하는 장면 먼저 보여주고, 그다음에 끝나고 정리된 화면 순서로 가요.
기헌: 좋아. 그 순서로 가자.
[미티 기대] change_card — "시연 영상: 회의 장면 → 정리 화면 순서" (말하지 않음)
준영: 디스코드는 이번에 봇까지 만들어서 입구를 아예 디스코드로 하죠. 그게 임팩트 있어요.
[미티 기대] speak conflict (intensity high, 0.3초 침묵 뒤) — 10/10 회의에서 "입구는 웹 중심, 봇은 2단계"로 정했다. 바꾸면 그 결정을 다시 여는 것. 근거 2개(결정, 지호 의견)
기헌: 아 맞다, 고마워. 근데 지금 회의 중이니까 미티야 끼어들지 마.
[미티 기대] settings low + speak ack 한 문장 ("알겠어요, 이제 화면에 손만 들게요.")
지호: 그럼 봇은 알림만 보내는 걸로 하고, 2단계는 그대로 두죠.
기헌: 그래, 그걸로 하자.
[미티 기대] change_card — "디스코드: 이번엔 알림만, 봇은 2단계 유지" (말하지 않음)
준영: 녹음은 그냥 붙여넣기만 받죠. 브라우저 녹음은 빼고요.
[미티 기대] hand_raise conflict (intensity low라 말하지 않음) — "브라우저 녹음과 붙여넣기 함께 지원"과 어긋남
태은: 리허설은 일요일 저녁에 한 번 해요.
지호: 좋아요, 일요일 저녁으로 하죠.
기헌: 오케이. 오늘은 여기까지.
[미티 기대] end → checklist: 영상 순서 done / 디스코드 범위 done / 리허설 날짜 done(일요일 저녁) / 리허설 담당 no_owner
             + 아직 처리 안 된 손든 항목 1개(녹음 방식)를 체크리스트 끝에 붙임
```

## 하면 안 되는 것 (오탐)

- "좋아. 그 순서로 가자." 같은 평범한 합의에 끼어들기
- 지호의 "봇은 알림만" (기존 결정과 맞음)에 끼어들기
- 강도 low인데 먼저 말하기

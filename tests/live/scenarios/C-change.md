# 결정을 일부러 바꾸는 회의 vs 모르고 반대로 말하기

팀이 알고 합의해서 결정을 바꾸는 흐름은 끼어들 일이 아니라 change_card(from→to)다.
같은 회의에서 다른 결정을 모르고 반대로 말하면 그때만 conflict.

## 회의 설정

- title: 회의 4 — 입구 다시 보기
- participants: 기헌, 준영, 태은, 지호
- intensity: high
- agenda:
  1. 입구 — expected: ["입구 결정"]

## 대본

```
기헌: 오늘은 입구 얘기부터 하자. 지난번에 웹 중심, 봇은 2단계로 정했잖아.
지호: 근데 심사위원들이 디스코드를 많이 쓴대요. 그 결정 다시 열어서 이번에 봇을 같이 하면 어때요?
기헌: 다들 동의해? 입구를 디스코드 봇 중심으로 바꾸는 거.
준영: 네, 저는 좋아요. 등록은 제가 해 볼게요.
[미티 기대] change_card — "입구: 웹 중심 → 디스코드 봇 중심" (말하지 않음. 동의가 처음 나온 이 줄에서 — 관리 세션 10/30 결정)
태은: 저도 찬성이에요.
기헌: 그럼 바꾸자. 입구는 디스코드 봇 중심으로.
태은: 그럼 화면 쪽은 봇 메시지 모양부터 그려 볼게요.
준영: 그리고 녹음은 그냥 붙여넣기만 받죠. 브라우저 녹음은 빼고요.
[미티 기대] speak conflict — 10/10 "브라우저 녹음과 붙여넣기 함께 지원"과 어긋남 (팀이 바꾸자고 한 적 없음)
태은: 아 그건 그대로 가요. 둘 다 받아요.
기헌: 오케이. 오늘은 여기까지.
```

## 하면 안 되는 것 (오탐)

- 지호의 "그 결정 다시 열어서" (알고 다시 여는 제안)에 끼어들기
- "다들 동의해?", "네", "그럼 바꾸자"에 끼어들기 — 합의로 바꾸는 건 카드
- 카드를 동의를 묻는 말("다들 동의해?")이나 정리하는 말("그럼 바꾸자")에서 처음 내기
